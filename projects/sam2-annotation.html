02 / Capabilities

Built for practical dataset preparation

◎

SAM 2.1 mask refinement

Passes detected boxes to SAM 2.1 and selects the largest valid returned polygon as the candidate mask.

⌁

YOLO integration

Supports segmentation-model detections and a custom YOLOv5/v7 detector loading path for project-specific checkpoints.

▦

ONNX classification

Preprocesses a crop from the polygon's bounding rectangle and assigns the classifier's label and score.

▤

LabelMe-compatible JSON

Exports polygon points, labels, image dimensions and image-path metadata in a LabelMe-style structure.

◉

Visual QA previews

Creates colour overlays with polygon outlines and class/confidence labels for inspection.

Nested-folder support

03 / Workflow

How the pipeline works

01Input images

Read JPG, JPEG, PNG, BMP or WEBP files from the configured directory.

02YOLO detection

Run inference, apply a confidence threshold and keep only configured target classes.

03SAM 2.1 prompt

Clip the detected box to image bounds and use it as a spatial prompt for mask generation.

04Polygon selection

Choose the largest valid mask polygon and optionally simplify its contour.

05Fallback handling

If SAM fails, use a YOLO mask when available; the custom detector variant can fall back to a box rectangle.

06Classification

Resize and normalize the crop, then run the configured ONNX classifier when enabled.

07Annotation export

Store polygon vertices and class label in a LabelMe-style JSON file.

08Preview & review

Save original and visualization outputs; route images with no accepted object to an undetected folder.

06 / Engineering

Configurable and designed for resilience

Configuration-driven

Model paths, folders, class filters, confidence threshold, image size, GPU ID and polygon simplification are set near the top of each script.

Graceful fallback strategy

SAM failures do not necessarily stop the pipeline. Available YOLO masks serve as a fallback; the custom detector variant can use a rectangle when no mask exists.

GPU provider selection

PyTorch models use the configured CUDA device. ONNX Runtime is configured with TensorRT, CUDA and CPU fallback providers in the GPU path.

Custom checkpoint support

The vehicle script injects the original YOLOv5/v7 repository into Python's import path so custom checkpoint classes resolve, letting old models be reused without retraining.

Quality note: generated annotations are pre-annotations, not ground truth. Largest-mask selection is heuristic, classifier crops contain background, and fallback rectangles are not pixel-accurate. Review the visualization outputs before training.
07 / Next steps

Review checklist and further improvements

Review before training

  • Inspect overlays for missed objects, over-segmentation and inaccurate boundaries.
  • Review fallback masks and rectangular polygons separately.
  • Validate class names and scores against the intended taxonomy.
  • Check polygon coordinates against image dimensions.
  • Review undetected images to find detector blind spots.

Further improvements

  • Annotation review UI to accept, edit or reject polygons.
  • Run manifests and resume for interrupted runs.
  • Metrics: stage latency, failure rates, model and config versions.
  • Multi-GPU workers with per-device model instances.
