01 / Overview

One operational view, many distributed stores.

◎

The challenge

When stores, edge devices, cloud services and cameras are spread across many locations, manual checks make it hard to spot failures quickly or see where an issue began.

Network outages, delayed events, low disk space, hardware stress and camera problems can go unnoticed until someone reports them.

↗

The solution

Automated Python workers collect operational data on a schedule, store current and historical results in daily SQLite databases and feed a Streamlit dashboard.

Alert logic flags prolonged edge/cloud delays, while camera snapshots give visual evidence for investigation.

02 / Capabilities

What the platform monitors

⌁

Connectivity & ports

Checks store reachability and verifies configured service ports to spot network or service availability issues.

⇄

Edge vs. cloud events

Compares event timestamps and surfaces delays so teams can tell local edge problems from cloud-side ones.

▤

Device health

Collects CPU, memory, disk availability and temperature to spot infrastructure risks.

▣

Camera snapshots

Collects RTSP snapshots and stores them for visual checks from the dashboard.

◉

Automated alerts

A supervisor process evaluates delay thresholds and sends Microsoft Teams notifications.

⌘

MCP data access

A read-only MCP interface lets approved tools and AI workflows query structured monitoring data.

07 / Impact

Operational value

For operations teams

  • See the health of many stores in one place.
  • Identify offline stores and unavailable services faster.
  • Review camera snapshots without visiting the store.
  • Receive alerts when delay thresholds are exceeded.

For engineering teams

  • Investigate historical records and recurring incidents.
  • Compare edge and cloud event timing.
  • Inspect device resource usage and storage availability.
  • Expose structured, read-only monitoring data to integrations.
The system replaces repeated manual checks with scheduled workers, historical records, dashboards and Teams alerts for device down and events not pushing. Admins can also query it through Claude via MCP.
